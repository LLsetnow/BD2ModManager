# 本地服装皮肤

`BD2CostumeSkins` 是 BD2ModManager 内置的独立 BepInEx 插件。首个预设为莉亚特里斯「女仆代号 R」`001207` →「甜蜜的诱惑」`001297`。

- 游戏角色页面选中来源服装后，小人上方显示原生 **Skin** 按钮。每次点击按「原版、已启用的目标皮肤」顺序循环，并保存选择。
- ModManager 的 **皮肤映射** 页面提供添加、移除、名称、启停、当前皮肤及插件安装。角色详情中也有入口。
- 添加、删除、启停和皮肤选择立即自动保存；名称在编辑完成或按回车后保存。修改按顺序提交到最新配置，仅更新本次操作，保留游戏内刚更改的其他皮肤选择；失败时显示错误并恢复已保存状态。
- 页面顶部总开关控制全部本地映射；关闭后沿用游戏原有外观，保留单项启停和选择。保存后自动刷新，重新开启即可恢复。
- 配置为 `BepInEx/plugins/BD2CostumeSkins/settings.json`，管理器另外保存一份到应用数据目录 `costume-skins.json`。游戏每秒检测配置变化，打开的角色页会刷新。
- 新增映射仅允许同一角色，目标不能同时作为其他映射的来源，避免循环和重复映射。

## 资源与接入

游戏已有独立于服装数值的 `CostumeDesignId`。插件覆盖该计算结果，让原生资源加载流程按目标设计 ID 选择立绘、`CostumeDesignConceptInfoTable` 背景、SD 模型及演出资源。`001297` 的素材已存在于本地素材库及游戏 Addressables 资源索引，无需重新打包图片。

角色页的技能预览回调额外直接读取 `Id` / `DesignId`，因此只对该回调中的两处读取转为计算后的设计 ID。补丁按签名发现资源查询和回调，并校验两处指令；无法兼容时撤销本插件全部补丁。

`CostumeDBInfo.Id`、`DesignId` 及其他 protobuf 字段不被修改。Skin 点击拦截原生皮肤设置请求，只写本地配置。没有启用映射的服装沿用原生流程；目标设计缺失时保留原生设计并提示错误。

BrownDustX 继续按最终目标资源名匹配模组。因此 `001297` 的已启用模组可以作用于该皮肤，`001207` 的资源替换不会被复制到目标 ID。

## 构建与验证

Manager 的 `build:game-plugin` 同时构建本插件和互动插件，并嵌入管理器安装资源。`GameRoot` 可通过 `BD2_GAME_ROOT` 覆盖。当前目标为 Unity Mono / BepInEx 5，.NET Standard 2.1。

`tests/SkinTests.csproj` 验证切换循环、停用、原版回退及无效映射；Rust `skins::tests` 验证角色归属、编号、循环、重复项及 JSON 编号保真。实际立绘、背景、技能播放和来回切换仍需游戏内复测。
